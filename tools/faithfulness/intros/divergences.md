Every place where the C# deliberately behaves differently from the original, collected from the
`// DIVERGENCE:` comments in `src/`. Each entry names where it is in the C# (file:line,
type.member), the original function(s) (by coordinate) from the nearest `// orig:` comment above it, and the
reason given in the comment (`why`). The class is derived by `tools/faithfulness/registers.py`
(a keyword heuristic, corrected by `tools/faithfulness/overrides.csv`):

| Class | Meaning |
|---|---|
| `undefined-memory` | the original reads or writes outside its defined data: garbage, out of bounds, uninitialised variables, stack leftovers, stale globals, a null far pointer |
| `host` | input/output, timing, rendering, audio, files, DOS/EMS, the clock |
| `not-modelled` | a feature or state that is not implemented yet (or is done by another layer) |
| `deliberate-fix` | the original would hang or crash, or has a defect, and the C# does not |
| `other` | a representation difference or anything else |

Core logic (rules, cards, events, travel, battles, persistence) comes first; presentation and
host entries follow. The `not-modelled`, `deliberate-fix` and `other` entries of the core logic,
and the `undefined-memory` ones, are reviewed in [DIVERGENCE_REVIEW.md](DIVERGENCE_REVIEW.md).
`divergences.csv` holds the same data for filtering. Entry ids are stable (a hash of the file and
the start of the note); do not edit this file, edit the comments and regenerate with
`python tools/faithfulness/registers.py`.
